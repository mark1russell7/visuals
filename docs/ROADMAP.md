# Roadmap

This file is the plan of visuals. The Status page of the site reads it, and the tracker of the project mirrors it.

| ID | Item | Status | Summary |
| --- | --- | --- | --- |
| R1 | The stage core | done | `@mark1russell7/visuals` has a stage on three.js: a camera that a person moves, views by name, picking, highlights, themes and a picture only after a change. The camera maths is pure, so a test in Node.js examines it. The stage comes from the viewer of `@mark1russell7/room-view`. Version 0.1.0 is on npm. |
| R2 | The globe | in progress | A content for a stage that shows the Earth: from the whole Earth to one region, with areas and points as data. Version 0.1.1 has it in the entry `/globe`: surfaces that follow the curve of the Earth, outlines, a grid, styles by kind, picking and a filter. The sphere maths is in `@mark1russell7/geo` 0.5.0. The home page of the site shows it with sample data. In version 0.2.3, the surface at the middle of the picture follows the pointer in a drag, at each height of the camera. In version 0.2.4, a view of regions fills the width or the height of the picture, and `stageSupported` tells a page if it loads the stage. In version 0.3.1, a style with `dash` draws the edge of its areas as a dashed line. Next: the place under the pointer. |
| R3 | The time scrubber | in progress | A control that replays how records change with time, for each stage. Version 0.2.1 has it in the entry `/scrubber`, with the style sheet `/scrubber.css`: a slider on an axis with a tick at each change, a button for the replay and a button for the speed. The model of a replay is in the root entry and needs no browser. The control writes no inline style, so a strict content security policy permits it. Next: the scrubber in the alerts command view, on the history of real records. |
| R4 | Marks | in progress | The marks that each viewer draws: a point, a run, a link, a field and a meter, each with a level. Version 0.2.0 has them as plain data in the entry `/marks`, with the shape of each level and `checkMarks`. The entry imports no three.js, so a package with no browser gives marks. The state of the pointer and of the selection has the new name highlight. In version 0.3.0, a meter can have no limit: the first add-on of room-view found this gap. Next: the content that draws the marks on a stage, with the signs that turn to the camera and the dashed links of room-view. |
| R5 | The room viewer on the stage | open | `@mark1russell7/room-view` builds its viewer on the stage, and keeps only the model of a room. |
| R6 | The demo site | in progress | The site becomes a live demo: a stage with sample data that a person turns, selects and replays. The home page has a live globe with sample warnings and earthquakes: a list that selects a record, a legend that filters, and three views. A browser with no WebGL 2 gets a flat map. The scrubber replays three days of the sample: the areas come, change their level, move and go. Next: the marks of a room on a stage. |
| R7 | The labels | in progress | The names of the places of a stage, as texts of the page. Version 0.2.2 has them in the entry `/labels`, with the style sheet `/labels.css`. Each text is next to its point, off each other text and off each mark. `placeLabels` is the pure function of the places. `stackContents` shows the layer with the content that it names. The home page names the place of each earthquake. Next: the names of the areas on the home page, with `bboxCenter` of `@mark1russell7/geo` 0.5.2. |
